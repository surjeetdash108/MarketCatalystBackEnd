How MarketCatalyst works

The whole system, in one picture

There are really just three things going on: your browser reads the database live, asks a price service for moving prices, and a background collector keeps the database fresh. Everything else supports those three.

Read: browser ↔ database Live prices: browser → price service → vendors Refresh: timer → collector → database

The three flows, in plain words

Read them top to bottom — that's the whole system.

1

Reading data

Your browser talks to the database directly and live. Open any screen — companies, earnings, movers, news — and the data appears, then keeps updating on its own. No server sits in between.

Firestore realtime listeners (onSnapshot). Your own data (watchlist, portfolio) is saved back the same way.
2

Live prices

Moving prices and the ticker tape come from a small public price service that fetches from the market-data vendor (Polygon). One fetch is shared by every user, so it stays fast and cheap — no matter how many people are online.

Cloud Run "live" service · cached polling + a shared SSE stream · ~15-min delayed on the current plan.
3

Refreshing the data

On a timer, a separate private collector pulls fresh company data, earnings and news from the vendors and saves it into the database — which your browser then shows through flow 1. This runs quietly in the background; users never touch it.

Cloud Scheduler → private "worker" Cloud Run → vendors → writes Firestore. 22 jobs on a schedule.

Components, explained

What each box actually is.

Browser SPA
Next.js · static export
The app. Client components + Redux (auth/profile). Reads Firestore directly and calls the live service; holds no vendor keys.
Cloud Firestore
client SDK + Admin SDK
The single source of truth for domain data (companies, prices, earnings, news…). Browser reads live via onSnapshot; the worker writes it server-side.
live · Cloud Run
APP_ROLE=live · public
Mounts only the LiveModule. Serves /live/snapshot, the SSE /live/tape/stream and /live/market-status. No admin routes exist here.
worker · Cloud Run
APP_ROLE=worker · private
Same image, all the sync/admin/plans modules. Only Cloud Scheduler (OIDC) can reach it. Runs the 22 ingestion jobs.
Cloud Scheduler
22 jobs · OIDC
Fires POST /sync/{job}/run on each job's cron with a signed OIDC token for the scheduler-invoker service account.
Polygon / Massive
REST · ~15m delayed
The market-data vendor. The only vendor whose data reaches users (licensed for redistribution). See the endpoint list below.
Firebase Auth · Hosting
tokens · static files
Auth issues the ID token that Firestore rules check; Hosting serves the compiled app bundle.
Secret Manager · Sentry
keys · errors
Secret Manager injects vendor keys into both services at startup; Sentry captures runtime errors (DSN-gated).

Polygon APIs we call

All 15 Polygon / Massive endpoints in the pipeline, with a real trimmed response captured from our key. Requests are simple GETs; apiKey and paging omitted for clarity.

At a glance — every endpoint we call
  1. 1/v3/snapshot — live delayed quotes
  2. 2/v2/aggs/ticker/…/range/… — OHLCV bars (daily + intraday)
  3. 3/v2/aggs/grouped/…/{date} — whole-market EOD
  4. 4/vX/reference/financials — income/balance/cash-flow
  5. 5/v3/reference/tickers/{t} — company details
  6. 6/v3/reference/tickers — ticker universe (list)
  7. 7/v3/reference/dividends — dividend history
  8. 8/v3/reference/splits — stock splits
  9. 9/vX/reference/ipos — IPO calendar
  10. 10/v3/reference/options/contracts — option chains
  11. 11/v2/reference/news — news + sentiment
  12. 12/v1/marketstatus/now — session state
  13. 13/v1/marketstatus/upcoming — market holidays
  14. 14/fed/v1/treasury-yields — yield curve
  15. 15/v1/related-companies/{t} — peers
