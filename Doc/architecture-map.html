The load-bearing rule

Domain data flows Browser ⇄ Firestore (paths 3–4) — everything the app renders, in real time, with no backend in the path. User-owned writes go straight back, scoped by firestore.rules.

The backend HTTP paths (5–8) add only moving prices and market status. The worker never serves the browser, and non-redistributable vendor data (FMP / Finnhub) never leaves the worker — only Polygon/Massive, which is licensed for redistribution, reaches a user.

FIG.2

Three ways data reaches the screen

Read paths differ by what they carry and how fresh it must be. A fourth flow — ingestion — fills the collections the first one reads.

Real-time · Firestore

Direct document reads

All domain data — companies, indices, movers, earnings, news, financials, recaps, sentiment, plans — via client-SDK onSnapshot. Live, cache-free, no backend hop.

paths 3 · 4
Polled · cached HTTP

Delayed prices & status

The public live service serves batched quotes every 15s (no-store + ETag) and the market-status pill. The server collapses N browsers into one vendor call.

paths 5 · 7 → 8
Streamed · SSE

The ticker tape

One ReplaySubject broadcast over Server-Sent Events. One upstream vendor call per minute fans out to every connected user, regardless of count.

path 6 → 8
Ingestion · write side

The refresh pipeline

Cloud Scheduler fires the private worker on cron; it calls the vendors through a fallback adapter and writes every collection with the Admin SDK.

All fourteen paths

Client ⇄ Firebase
1Hosting → Browser
HTTPS · static
The Next.js out/ bundle and assets, served from Firebase Hosting.
2Browser ⇄ Auth
Firebase SDK
Sign-in / up, onAuthStateChanged, 1-hour ID tokens → Redux via FirebaseListener.
3Firestore → Browser
Client SDK · onSnapshot
All domain data: companies, market_indices, movers, sectors, breadth, earnings, news, financials, dividends, ipos, recaps, sentiment, plans.
4Browser → Firestore
Client SDK · owner-scoped
User-owned writes: watchlists, portfolio holdings, settings, stock_comments, feature_adoption.
Client ⇄ Backend (public live service)
5Browser → live
GET /live/snapshot · 15s
Batched delayed quotes for the shared live-price subscription (watchlist, portfolio, search, stock detail). cache:no-store + If-None-Match.
6Browser ⇄ live
SSE · /live/tape/stream
The header ticker tape. One ReplaySubject broadcast — one vendor call/min serves every user.
7Browser → live
GET /live/market-status
Session pill (pre / open / after / closed) and extended-hours state.
8live → Polygon
HTTPS · on demand
/v3/snapshot (tape + quote tickers) and /fed/v1/treasury-yields. Ref-counted; ~15m delayed.
Backend internals (private worker · infra)
9Scheduler → worker
POST /sync/*/run · OIDC
22 cron jobs (ET) fire the ingestion pipeline. Token minted for the scheduler-invoker service account.
10worker → Vendors
HTTPS · fallback adapter
Polygon (redistributable) + FMP / Finnhub / SEC EDGAR / FRED. Non-redistributable feeds stay worker-side.
11worker → Firestore
Firebase Admin SDK
Writes every synced collection + sync_meta. The recaps job composes existing collections into a daily snapshot.
12Secret Manager → both
env injection · startup
Vendor API keys, injected into live and worker — never in code or env files.
13Admin iframe ⇄ parent
postMessage · sessionStorage
Admin dataset staged before the iframe mounts; plan-flag writes delegated to the parent's client SDK.
14Browser + worker → Sentry
HTTPS · DSN-gated
Error / exception capture. A no-op until the DSN is configured.
