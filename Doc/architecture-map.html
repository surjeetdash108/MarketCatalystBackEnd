MarketCatalyst Backend · implementation map

Current backend architecture

A code-led map of the NestJS backend: two Cloud Run roles from one image, a public live-data surface, a private worker surface, Firestore cache and domain storage, and a single Scheduler-backed premarket orchestration run.

Scope and audit date. This map is based on this backend repository as inspected on 2026-07-27: src/, deploy/, firebase.json, and Firestore configuration. A box is marked when it is configured in a separate UI repository or is unreliable with the deployed scale-to-zero model.
Two environments (2026-07-27). The topology below exists twice, once per isolated Firebase project: market-catalyst-502415 (prod) and market-catalyst-stage (stage). Each project has its own Firestore (nam5), Auth, rules, and backend-runtime service account; stage was seeded with a full copy of prod data. Nothing is hardcoded to one project — the backend selects the project by FIREBASE_PROJECT_ID (deploy/env.<env>.yaml) and the UI by NEXT_PUBLIC_FIREBASE_* (stage build via .env.production). The UI's backend base URL is resolved at runtime — localhost:4100 in dev, same-origin when deployed — so the same static build runs against either environment. Both repos develop on the stage branch.

Deployed topology

One container image is deployed twice. The public service has no worker or admin routes mounted; this is a route-surface boundary, not merely an authorization check.

Runtime roles and boundaries

Public role

live Cloud Run

Mounts LiveModule and /health. It is intentionally --allow-unauthenticated for browser SSE. The application does not mount sync, purge, retention, feature flags, plans, admin analytics, or the worker ops screen in this role.

Private role

worker Cloud Run

Mounts all backend modules and is intended to run behind Cloud Run IAM. Scheduler and privileged operators use OIDC/IAM; the process uses Application Default Credentials to access Firestore and Secret Manager-injected API keys.

Storage and identity

Firebase

The browser uses Firebase Auth only (identity); market and user data come from this service's REST/SSE surface, not direct Firestore reads. The project is selected per environment by FIREBASE_PROJECT_ID — market-catalyst-502415 (prod) or market-catalyst-stage (stage) — and the backend uses the Firebase Admin SDK (ADC via the backend-runtime service account), bypassing Firestore rules for server writes. SENTRY_DSN enables process-level exception reporting.

Configuration caveat

Hosting rewrites are external

This repository's firebase.json declares only Firestore rules and indexes. The Hosting rewrites that make the UI reach this service same-origin — /api/**, /market-data/**, /live/** → market-catalyst-live — ship from the UI repo's firebase.json, so they cannot be verified from this repo alone. They require the Cloud Run API + billing on the target project; the free-tier stage project currently ships only the SPA catch-all until billing is linked.

Public live-data surface

All routes below are mounted in the public live role. They have no application authentication guard; cache headers and CORS are the primary browser-facing controls.

Route Implementation Cache / stream behavior
GET /health Basic process health response; mounted in both roles. No data dependency.
GET /live/bars
GET /live/company 		On-demand cache-aside reads. Service checks in-memory data, then Firestore, then makes a coalesced Polygon request and writes the shared cache. Bars: 60s CDN/browser contract; company: 300s. Bars use one stock_bars/{ticker}_{resolution} document per resolution; daily ranges widen in place.
GET /live/search Substring search against the Polygon reference universe kept in service memory. One-hour cache header; no Firestore reads per search. The universe is loaded/refreshed by the service, not from tickers.
GET /live/snapshot Demand-driven shared quote cache for up to 50 tickers per request. 5s browser / 10s shared cache + ETag. At most one Polygon universal-snapshot fetch per refresh window per live instance; no regular refresh outside extended session.
GET /live/tape
GET /live/tape/stream 		Shared tape frame and ref-counted SSE broadcast. The tape fetches a configured small universe and a cached Treasury tile. JSON has 30s browser / 60s shared-cache headers and ETag. SSE is direct to Cloud Run, sends tape frames plus 20s heartbeats, and stops its poller when no viewers remain.
GET /live/stream?ticker=… Ticker-specific SSE bridge through PolygonLiveService, including an initial previous-close snapshot. Direct SSE. This is distinct from the shared tape stream and uses Polygon's delayed aggregate WebSocket path.
GET /live/collections Allow-listed shared Firestore collections served through a server-side cache. 120s browser / 300s shared cache + ETag. Avoids one Firestore read per user for slow-changing shared collections.
GET /live/market-status
GET /live/whoami
GET /live/*/stats 		Market session status, first-party IP echo, and cache/stream observability. Status: 30s browser / 60s shared cache. whoami and stats are no-store.

API request and response reference

Public examples below follow the controllers in src/live/. JSON calls receive the listed Cache-Control and ETag behavior; an If-None-Match match receives 304 with no body.

GET /live/bars?ticker=AAPL&tf=1Y On-demand chart series

Valid timeframes: 1H, 1D, 1W, 1M, 3M, 6M, 1Y, 5Y. Ticker must match [A-Z0-9.-]{1,10}. The service reads a resolution family from memory/Firestore, or coalesces a Polygon aggregate call on a cache miss. Response header: Cache-Control: public, max-age=60, s-maxage=60, stale-while-revalidate=120. 

{
  "ticker": "AAPL",
  "tf": "1Y",
  "bars": [
    { "t": 1721620800000, "o": 211.09, "h": 214.85,
      "l": 210.72, "c": 214.24, "v": 62997800, "vw": 213.51 }
  ],
  "source": "memory",
  "asOf": "2026-07-26T02:30:00.000Z"
}
GET /live/company?ticker=AAPL On-demand company + delayed price

Merges the profile and quote into companies/AAPL on a miss without overwriting fields generated by batch jobs. The company cache freshness window is 20 hours; the HTTP response is cacheable for five minutes. Returns 404 only when neither a Polygon profile nor a quote is available. 

{
  "ticker": "AAPL", "name": "Apple Inc.",
  "sector": "ELECTRONIC COMPUTERS", "marketCap": 3210000000000,
  "exchange": "XNAS", "price": 214.24, "pctChange": 1.14,
  "prevClose": 211.83, "volume": 62997800,
  "createdAt": "2026-07-26T02:30:10.000Z",
  "updatedAt": "2026-07-26T02:30:10.000Z",
  "source": "polygon-ondemand"
}
GET /live/search?q=apple Ticker and company-name search

Query is required and limited to 40 characters. Results are ranked exact ticker → ticker prefix → company-name prefix → substring and limited to 20. The endpoint searches a 24-hour in-memory Polygon reference universe, so it performs no Firestore reads. 

{
  "q": "apple",
  "results": [
    { "ticker": "AAPL", "name": "Apple Inc." },
    { "ticker": "APLE", "name": "Apple Hospitality REIT, Inc." }
  ]
}
GET /live/snapshot?tickers=AAPL,MSFT,NVDA Batched delayed quotes

Accepts 1–50 valid tickers. Requests register demand in the shared cache; an initial uncached request may fill the cache, then a demand-driven timer refreshes the tracked set. Response header: max-age=5, s-maxage=10, stale-while-revalidate=30. Quotes are frozen outside the extended session except for an uncached cold start.

GET /live/collections?names=market_indices,sectors Shared Firestore collection cache

Only the server allow-list is accepted (for example: companies, indices, movers, sectors, breadth, sentiment, earnings, IPOs, macro, recaps, and insider transactions). At most 24 names may be requested. The response is a map of arrays whose objects are prefixed with Firestore document IDs; it is cacheable for two minutes in browsers and five minutes at shared caches. 

{
  "market_indices": [
    { "id": "SPY", "symbol": "SPY", "price": 540.12, "asOfDate": "2026-07-25" }
  ],
  "sectors": [
    { "id": "XLK", "symbol": "XLK", "changePct": 0.73, "asOfDate": "2026-07-25" }
  ]
}
SSE GET /live/tape/stream Shared header tape

A direct Cloud Run EventSource endpoint. It emits tape frames from a common replay buffer and a heartbeat event every 20 seconds. One tape poller is shared by every connected viewer; the JSON fallback is GET /live/tape.

SSE GET /live/stream?ticker=AAPL Per-ticker delayed aggregate stream

Ticker must contain only uppercase A–Z and periods (1–10 characters). The stream emits a startup status, an initial previous-close snapshot, connection statuses, and delayed aggregate tick events from the Polygon WebSocket bridge.

On-demand data and Firestore

Shared cache-aside

Company and chart data

companies/{ticker} stores company data and stock_bars/{ticker}_{resolution} stores compact bar arrays. Freshness is evaluated from ISO createdAt; daily and intraday ranges have different TTLs.

Demand feedback

ticker_usage

On-demand bars and company reads accumulate usage and flush it at most once per ticker per minute. The worker reads the top 100 used tickers as part of its next warm set.

Domain collections

Batch outputs

The worker writes market, reference, financial, news, SEC, options, history, and recap data. Operational state lives in sync_meta and sync_watermarks; payments/plans live in their own collections.

User-owned paths

Users and notifications

Watchlists, portfolios, holdings, settings, sessions, and notifications are under user paths. Important news fans out to matching users’ notification subcollections, then is pruned to 100 items / 30 days per user.

The backend repository’s firestore.rules explicitly says it is not the deployed ruleset; production rules are maintained in the UI repository. Do not treat this repository’s rules file as the source of truth for browser access.

What is actually scheduled

There are two distinct mechanisms in the codebase: the Scheduler-backed premarket run and in-process @Cron tasks.

Mechanism Trigger Work performed Production reliability
Cloud Scheduler
sync-premarket		 0 8 * * 1-5, America/New_York; OIDC POST /sync/premarket/run. Warm tape symbols + user watchlist/portfolio holdings + top usage tickers; then market-wide jobs, per-ticker jobs over companies, then recaps. Authoritative production schedule. deploy/create-scheduler-jobs.sh creates/updates this entry and deletes the retired per-job Scheduler names it knows about.
Sync registry metadata
Individual job cron fields 		Each job registers its former cadence for /sync/jobs visibility and manual triggers. The underlying jobs are invoked by the premarket orchestrator where listed; the metadata itself does not create a Nest cron task. Not an execution schedule. The legacy 01:00–19:00 times should not be read as active Cloud Scheduler calls.
In-process decorators
auto-purge, retention 		Midnight daily ET and Sunday 05:00 ET, respectively, using @Cron. Auto-purges stale ephemeral collections; retention prunes historical market, sector, news, and OHLCV records. Best-effort only. The worker is documented as scale-to-zero, so no process exists to fire these decorators unless an instance happens to be running. They need Scheduler jobs or another durable trigger to be guaranteed.
Operational discrepancy to resolve. The currently deployed worker model relies on Cloud Scheduler for durable timing, but auto-purge and retention rely on in-process timers. This map reports their code behavior; it does not claim that they reliably run in production.

Premarket orchestrator

The one Scheduler invocation deliberately replaces the old independent batch schedule. A failure in one phase job is recorded and does not stop later jobs.

Phase 1 · warm

Hot set through on-demand cache

Tape symbols, all user watchlist/portfolio symbols, and the top usage list receive company, 1Y daily-bar, and 1D intraday-bar requests.

Phase 2 · market-wide

Shared market collections

Indices, sectors, movers, breadth, Fear & Greed, macro, earnings, IPOs, news, analyst actions, Form 4, 13F, dividends, and options chains.

Phase 3 · per ticker

Active company universe

Companies, historical OHLCV, technical indicators, RS rating, tech rating, financials, fundamentals growth, and corporate actions run over existing companies documents rather than a fixed market universe.

Phase 4 · recap

Prior-session composition

The recap job runs last, after the data it summarizes. The standalone ticker-universe, market-quotes, and intraday-bars registry jobs are not part of this phase list.

Private operations and commercial surface

Area Routes / behavior Access control
Sync control GET /sync/jobs, status routes, manual POST /sync/:job/run, and POST /sync/run-all. Status reads are not decorated with AdminGuard; manual triggers are guarded. The entire controller exists only in the private worker role.
Destructive / lifecycle Purge preview/execute, retention preview/run, and auto-purge registry support. Purge requires a preview token before execution. AdminGuard plus private worker route surface. Retention and auto-purge execution are controlled by their dry-run environment flags.
Feature flags and plans Flag map and updates; public plan listing; guarded plan seed and user entitlement lookup; worker-only admin analytics for users, subscriptions, and revenue. Flag routes and sensitive plan/admin routes use AdminGuard; public plan listing remains mounted only in the private worker role.
Authorization model AdminGuard validates Firebase ID tokens for the configured admin email, or—when configured—trusts Cloud Run IAM after the private service has authenticated the caller. ADMIN_GUARD_TRUST_IAM=true is safe only while the worker remains private. The public live role avoids this risk by not mounting privileged modules.

External providers

Production primary

Polygon / Massive

The worker configuration selects Polygon for profiles, movers, news, dividends, IPOs, sectors, quotes, bars, ticker reference, and financials. The public live service also uses it for delayed snapshots, tape data, aggregates, reference search, and the ticker SSE bridge.

Direct worker sources

SEC EDGAR + FRED

SEC EDGAR provides Form 4 and 13F data. FRED supplies macro events. Both run from the worker-side sync modules.

Installed, not selected in production config

Fallback and Wave 3 clients

FMP and Finnhub are adapter-capable fallbacks, but current worker environment values select Polygon with fallback none. Benzinga, Tradier, and Unusual Whales services are mounted in the worker-only Wave3 module; no current controller route exposes them.

Implementation notes

  • The application is NestJS 11 on Node 22, built once in a multi-stage Docker image and run as the non-root node user.
  • The live role is designed for long-lived SSE connections; deployment guidance sets a 3,600-second timeout and 200 concurrency. The worker guidance uses a 900-second timeout, while the Scheduler script sets a 1,800-second attempt deadline—verify these values align with the actual longest premarket run.
  • The public cache story is layered: browser max-age, Hosting CDN s-maxage where the UI rewrite exists, in-instance caches, then Firestore as the durable shared cache. Direct SSE bypasses Hosting.
  • /live/stats, /live/tape/stats, and /live/ondemand-stats expose the cache/coalescing counters needed to verify that upstream calls scale with refresh windows rather than user count.
