How MarketCatalyst works

The whole system, in one picture

There are really just three things going on: your browser reads the database live, asks a price service for moving prices, and a background collector keeps the database fresh. Everything else supports those three.

Read: browser ↔ database Live prices: browser → price service → vendors Refresh: timer → collector → database

The three flows, in plain words

Read them top to bottom — that's the whole system.

1

Reading data

Your browser talks to the database directly and live. Open any screen — companies, earnings, movers, news — and the data appears, then keeps updating on its own. No server sits in between.

Firestore realtime listeners (onSnapshot). Your own data (watchlist, portfolio) is saved back the same way.
2

Live prices

Moving prices and the ticker tape come from a small public price service that fetches from the market-data vendor (Polygon). One fetch is shared by every user, so it stays fast and cheap — no matter how many people are online.

Cloud Run "live" service · cached polling + a shared SSE stream · ~15-min delayed on the current plan.
3

Refreshing the data

On a timer, a separate private collector pulls fresh company data, earnings and news from the vendors and saves it into the database — which your browser then shows through flow 1. This runs quietly in the background; users never touch it.

Cloud Scheduler → private "worker" Cloud Run → vendors → writes Firestore. 22 jobs on a schedule.
